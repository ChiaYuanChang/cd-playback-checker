# CD 播放測試（compare-audio）

用麥克風錄下 CD 播放器播出來的聲音，跟參考音檔自動對齊，找出**跳過、重播、卡住、停頓、瞬間無聲、提早停止、整首沒播**等問題。Windows 桌面程式（Python + PySide6），也能在 macOS 上開發和執行。

## 原理：畫一條「對齊線」

CD 是數位播放，不會忽快忽慢，所以正常播放時「錄音的第幾秒 → 參考音檔的第幾秒」是一條斜率固定的直線。跳針、卡住都會讓這條線斷掉：

| 線的樣子 | 判定 |
|---|---|
| 往上斷 | 跳過（漏播一段） |
| 往下斷 | 重播 |
| 位置不前進、錄音一直重複同一小段 | 卡住 |
| 位置不前進、錄音只剩環境音 | 停頓 |
| 位置照常前進，但錄音突然沒聲音 | 瞬間無聲 |
| 在兩首歌交界處暫停 | 曲間空白（正常） |

做法是把錄音每 0.25 秒切一段（每段 1.5 秒），用 log-mel 頻譜的正規化互相關（NCC）到參考音檔裡找位置：

- **不用同步起點**：按下開始後才走去按播放也沒關係，程式會自己在錄音中找到開頭。
- **5～6 首連續播放**：所有曲目接成一條時間軸，曲間空白多長都可以。
- **環境音**：每段都有比對分數。只有「很確定對到別的位置」才判成問題，對不上的標成「待確認」，讓你點進去聽。
- **時脈漂移**：CD 機和錄音裝置的時脈一般差幾十 ppm，便宜的 webcam 麥克風或播放器可能差到 0.3～0.5%（3000～5000 ppm）。程式會自動估計並補償（最多 ±1%，報告中會顯示）。

## 安裝與執行

### 開發環境（Windows / macOS）

需要 [uv](https://docs.astral.sh/uv/) 和 Python 3.12：

```bash
uv sync
uv run python -m compare_audio
```

### 打包成 Windows 程式

在 Windows 上執行（PyInstaller 無法在 Mac 上直接打包出 Windows 版）：

```bat
build_windows.bat
```

產生的 `dist\CompareAudio\` 整個資料夾複製到測試電腦上，執行 `CompareAudio.exe` 即可，不需要另外安裝 Python。

## 使用步驟

1. **測試片**：第一次使用時按「新增」，依播放順序加入那張 CD 的參考音檔（建議用從同一張 CD 抓下來的 WAV/FLAC 無損檔）。設定會存起來，之後直接從下拉選單選。
2. **麥克風**：選擇收音裝置，對著喇叭看音量表，確認有收到聲音、沒有爆音（CLIP 燈亮就是爆音）。
3. 按 **開始錄音**，再去 CD 播放器按播放。
4. 最後一首播完會自動停止，也可以隨時按 **停止**。程式接著會做完整分析（15 分鐘的錄音大約 2～4 秒）。
5. **結果頁**：
   - 最上方顯示 PASS / FAIL / 需人工確認
   - 三張可以縮放、同步連動的圖：對齊線、波形對照（預設同方向疊圖，可切換上下比較）、音量對照
   - 事件列表：點一下就會放大到那個時間點，可以按「▶ 播放錄音」和「▶ 播放參考」對照試聽
   - 「匯出報告…」會產生 HTML 報告（含圖表）、`events.csv`、`result.json`

錄音檔（WAV）和 `.result.json` 會存在「錄音存放位置」，之後可以用「檔案 → 分析錄音檔…」重新分析。

### 即時圖表與辨識靈敏度

- 錄音時也會顯示參考與收音的**振幅包絡**；參考已對齊並校正振幅。這是形狀比較，不是逐點相位比對，麥克風與房間會改變形狀。未對齊的參考保持空白。
- 初步異常、曲目覆蓋進度與對齊波形使用同一份分析結果，約每 5 秒更新（較慢的電腦可能更久）；目前播放位置持續更新。停止後會重新分析整段錄音，產生最終報告。
- 在圖上拖曳平移、滾輪縮放。參考位置圖支援水平與垂直操作，時間軸與下方兩圖連動。錄音時手動操作會關閉「自動跟隨」，勾回即可恢復；「全部顯示」還原全景。
- 「波形疊圖」讓兩個包絡朝同一方向；「波形上下比較」讓錄音向上、參考向下。錄音與結果頁都能切換。
- 左側「辨識靈敏度（當次測試）」可調整 0–100，50 保留原有門檻。小聲收音可試 60–80；靈敏度過高可能對錯位置。錄音中不能調整，停止後可更改並用「分析錄音檔…」比較結果。
- 「新增／編輯測試片」可儲存該片的預設靈敏度。左側拉桿只影響當次錄音、模擬或檔案分析，不覆寫測試片預設。
- 辨識資訊顯示近期匹配分數、估計背景音和對齊區段的訊噪比。匹配分數不代表播放器品質；訊噪比太低仍應改善收音。已找到內容但無法估計可靠音量時會標為需確認，避免在無法檢查短暫無聲時給出 PASS。
- JSON 報告包含 `analysis_config` 和 `recognition_thresholds`，HTML 也會顯示靈敏度及匹配/鎖定門檻，方便比較測試。

修改背景與驗收紀錄見 [使用者 feedback 規劃](docs/feedback-plan.md)。

### 直接從 CD 匯入參考音軌（.cda）

在 Windows 上把那張 CD 放進電腦的光碟機，然後：
1. 在「新增／編輯測試片」按「加入音檔…」。
2. 切到光碟機，選 `Track01.cda`、`Track02.cda` 等檔案，可以一次多選。

`.cda` 本身不是音訊檔，只是 Windows 替每一軌建立的 44 bytes 捷徑，記錄第幾軌、從光碟哪裡開始、多長，真正的聲音在光碟上。程式會直接讀光碟上的原始 CD 音訊，每一軌存成一個 16-bit WAV，跟光碟上的資料逐位元相同。存放位置是 `%APPDATA%\CompareAudio\CompareAudio\cd_audio\disc-XXXXXXXX\`。之後光碟可以拿去放進待測的 CD 機，不需要再放在電腦裡。

- 讀取時光碟必須在光碟機裡。只把 `.cda` 複製到別的地方是沒有用的，因為複製到的只是捷徑。
- 讀取速度取決於光碟機，一首 5 分鐘的歌大約十幾秒到一分鐘。
- 程式沒有做 EAC 那種反覆比對的「安全模式」讀取，請用乾淨、沒刮傷的光碟當參考。讀取失敗時會顯示光碟上出錯的位置。
- macOS 會把音樂 CD 顯示成 AIFF 音軌，直接選那些 `.aiff` 檔即可。

### 收音建議

- **麥克風離喇叭越近越好**（固定在 5～10 公分），效果比任何演算法都好，也能抓到更短的無聲。
- **關閉 Windows 的音訊增強、噪音抑制、自動增益**：控制台 → 聲音 → 錄製 → 麥克風內容。噪音抑制會把小聲的段落吃掉，看起來就像瞬間無聲。
- 盡量用外接 USB 麥克風。很多筆電的內建麥克風處理很重。
- 如果收到的訊號全是 0，請到「設定 → 隱私權 → 麥克風」允許桌面應用程式使用麥克風。
- 同一個空間如果有多台同時播同一張片，麥克風可能收到別台的聲音。這種情況請把麥克風貼近待測的喇叭。

## 沒有 CD 機也能試用

```bash
uv run python -m tools.make_test_set --out sample_data
```

這會產生 6 首程序化合成的測試音樂、一個測試片設定（`sample_data/synthetic_disc.profile.json`），以及 12 段模擬的麥克風錄音。這些錄音分成三種收音環境，並植入了各種問題，每段旁邊都有 `.truth.json` 記錄正確答案。

- 用「測試片 → 匯入…」選 `synthetic_disc.profile.json`。
- 用「檔案 → 用錄音檔模擬收音…」選 `sample_data/recordings/*.wav`，可以選 1、4 或 16 倍速，把錄音檔當成麥克風，走完整個錄音與即時分析流程。
- 也可以用「檔案 → 分析錄音檔…」直接分析。

## 準確度（合成資料評估）

```bash
uv run python -m tools.evaluate_detection --data sample_data --plots
```

評估用了兩組資料：
- 調整參數用的一組：12 段、每段約 6 分鐘。
- 完全沒拿來調參數的驗證組：12 段、每段約 15 分鐘，歌曲和情境都不一樣，還多了「近距離但有人講話」的情境。

模擬內容包括喇叭頻響、房間殘響、麥克風距離、粉紅雜訊、人聲、敲擊聲，以及 ±40～120 ppm 的時脈漂移。驗證組可以用下面的指令重新產生（約 1 GB，需要 5 分鐘左右）：

```bash
uv run python -m tools.make_test_set --out sample_data_holdout --track-seconds 150 --faulty-per-condition 2 --seed 99 --song-seed 200
uv run python -m tools.evaluate_detection --data sample_data_holdout --out eval_output/holdout
```

| 問題類型 | 調參組 | 驗證組 |
|---|---|---|
| 跳過 | 9/9 | 14/16 |
| 重播 | 14/14 | 6/7 |
| 卡住 | 7/7 | 10/11 |
| 停頓 | 4/4 | 3/3 |
| 後半首被跳過／整首沒播／中途停止 | 5/5 | 5/5 |
| 瞬間無聲 | 12/15 | 12/16 |
| 多報的 FAIL 事件 | 0 | 1（其實是正確的偵測，只是時間晚了 4 秒） |

- 沒有植入問題的 7 段乾淨錄音：6 段 PASS，1 段「需人工確認」（最吵的環境下，有一首的小聲前奏無法確認），沒有任何一段被判成 FAIL。
- 找到的問題，時間誤差中位數大約 10～25 ms，跳動長度誤差大約 1 ms。
- **瞬間無聲能抓到多短，取決於麥克風距離和殘響**：
  - 近距離：100 ms 以上都抓得到，30 ms 大約一半。
  - 中距離：60 ms 以上都抓得到。
  - 遠距離＋大殘響：100 ms 大約 3/4。
- 已知限制：
  - 如果音樂剛好「一模一樣地重複」（例如電子音樂的循環小節），跳過的時間點會晚到內容不一樣的地方才報出來。
  - 非常小聲的前奏或淡出在吵雜環境下可能無法確認，會標成「待確認」。
  - 以上是合成資料的結果，請用實際的 CD 和麥克風再驗證一次，必要時調整 `AnalysisConfig` 的門檻。門檻可以寫進測試片設定檔的 `analysis` 欄位。

## 專案結構

```
compare_audio/
├── core/          分析引擎（純 numpy/scipy，不依賴 Qt，可單獨測試）
│   ├── spectral_features.py   log-mel、能量與波形包絡（可串流）
│   ├── reference_program.py   載入參考曲目、接成一條時間軸、特徵快取
│   ├── window_matcher.py      NCC 局部／全域搜尋
│   ├── alignment_tracker.py   逐段對齊（即時與離線共用）
│   ├── event_detector.py      對齊點 → 事件（跳過、重播、卡住…）
│   ├── recording_analysis.py  離線分析整段錄音
│   ├── live_analysis.py       錄音中的即時分析
│   └── report_export.py       HTML / CSV / JSON 報告
├── audio/         sounddevice：列出麥克風、收音、用檔案模擬收音、試聽；cd_audio.py 讀取 CD 音軌（.cda）
├── profiles/      測試片設定檔（JSON）
└── ui/            PySide6 + pyqtgraph 介面
tools/             合成測試音樂、聲學模擬、評估工具
tests/             pytest
```

開發指令：

```bash
uv run pytest          # 測試
uv run ruff check .    # lint
uv run ruff format .   # 格式化
```
